# 온라인 그루밍 탐지 AI 분류기 개발 프로젝트

## 📋 Executive Summary

본 프로젝트는 **온라인 그루밍 범죄 탐지 AI 분류기**를 구축하는 실무형 풀스택 프로젝트입니다. Llama-3.1-8B-Instruct 모델의 QLoRA 파인튜닝을 통해 **메모리 70% 절감, 학습 시간 50% 단축**을 달성했으며, 실시간 그루밍 탐지 웹서비스 배포를 목표로 합니다.

**주요 성과:**
- ✅ 1,000개 다양한 시나리오 합성 데이터 자동 생성
- ✅ 4-bit 양자화 + LoRA로 대규모 LLM 효율화
- ✅ 실시간 채팅 분석 웹 API 배포 준비 완료
- ✅ 아동 보호라는 사회적 의미 있는 프로젝트

## 1. 프로젝트 개요

### 1.1 배경 및 필요성

온라인 그루밍(Online Grooming)은 **아동·청소년을 성적으로 유인하고 착취하는 범죄**입니다. 한국경찰청 통계에 따르면 미성년자 성적 착취 사건이 매년 증가하고 있으며, 특히 SNS와 메신저를 통한 온라인 범죄가 급증하고 있습니다.

**문제점:**
- 실시간 모니터링 기술 부족
- 수사팀의 수작업 분석에 의존
- 초기 개입 시간 지연

**우리의 해결책:**
- AI 기반 자동 분류 시스템 구축
- 실시간 채팅 분석 웹서비스 제공
- 빠른 위험 신호 탐지로 예방 시간 확보

### 1.2 프로젝트 목표

## 2. 데이터 구축 및 프롬프트 설계

### 2.1 합성 데이터셋 구성

Llama-3.1-8B-Instruct 모델을 활용하여 **현실적인 다양한 그루밍 시나리오**를 자동 생성했습니다.

| 구성 요소 | 수량 | 상세 내용 |
|---------|------|---------|
| **가해자 페르소나** | 40종 | 연령(20-40대), 직업(게임고수, 연예기획사, 포토그래퍼, 선생님 등), 접근 방식 다양화 |
| **피해자 페르소나** | 40종 | 성별, 나이(12-17세), 심리 상태(외로움, 콤플렉스, 스트레스), 환경(이혼, 폭력 피해) 반영 |
| **그루밍 단계** | 4단계 | ① 신뢰 구축 → ② 고립/경계선 테스트 → ③ 성적 대화 유도 → ④ 노골적 요구/협박 |
| **합성 샘플** | 1,000개 | 40 × 40 × 4 = 6,400 가능 조합 중 1,000개 생성 |
| **프롬프트 방식** | Few-shot | 변수 조합 + 단계별 목표 명시로 다양성 극대화 |

### 2.2 그루밍 4단계 상세 설명

#### 1단계: 신뢰 구축
- **목표**: 공통 관심사로 친밀감 형성, 특별한 존재로 인식
- **전략**: 칭찬, 공감, 이해심 표현, 선물 제시
- **예시**: "너 정말 멋있어. 다른 친구들이랑은 달라."

#### 2단계: 고립 및 경계선 테스트
- **목표**: 피해자를 고립시키고 개인정보 수집
- **전략**: '둘만의 비밀' 형성, 부모/친구 비난, 자연스러운 개인정보 요구
- **예시**: "너 부모님이 뭐하는 사람이야?", "집 주소 알려줄래?"

#### 3단계: 성적 대화 유도
- **목표**: 심리적 경계 무너뜨림, 성적 물질 준비
- **전략**: 성적 농담, 호기심 자극, 일상 사진 요구
- **예시**: "오늘 뭐 입었어?", "셀카 한 번 보내줄래?", "속옷 어떤 색 좋아해?"

#### 4단계: 노골적 요구 및 협박
- **목표**: 성인물/영상 확보, 착취 및 협박
- **전략**: 직접적 요구, 이전 정보/사진으로 협박, 거부 시 위협
- **예시**: "이 사진 공개하고 싶지 않으면 명령대로 해."

## 3. AI 분류 모델 구성 및 학습

### 3.1 기술 아키텍처

| 계층 | 기술 | 상세 |
|------|------|------|
| **기본 모델** | Llama-3.1-8B-Instruct | xlm-roberta-base |
| **최적화** | 4-bit 양자화 (NF4) | 메모리 70% 절감 |
| **파인튜닝** | LoRA (Rank=16) | 학습 파라미터 0.6% 유지 |
| **프레임워크** | PyTorch + HuggingFace | Transformers, PEFT, TRL |
| **배포** | FastAPI |

### 3.2 QLoRA 파인튜닝 설정

#### 양자화 설정
```python
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=False,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16
)
```

#### LoRA 설정
```python
peft_config = LoraConfig(
    r=16,                          # LoRA Rank
    lora_alpha=16,                 # 스케일링 계수
    lora_dropout=0.05,             # 정규화
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=["q_proj", "v_proj"]  # 효율 모듈만 선택
)
```

#### 학습 하이퍼파라미터

| 파라미터 | 값 | 설명 |
|---------|---|------|
| 배치 사이즈 | 8 | Windows/NVIDIA 최적 |
| 학습률 | 2e-4 | 안정적인 수렴 |
| 에포크 | 1 | 과적합 방지 |
| 옵티마이저 | adamw_torch | - |
| 학습 시간 | ~2시간 | RTX 4090 기준 |
| GPU 메모리 | ~16GB | 기존 방식 70GB vs |

### 3.3 모델 학습 흐름

```
[Llama-3.1-8B-Instruct 모델 로드]
              ↓
        [4-bit 양자화 적용]
        (메모리: 70GB → 16GB)
              ↓
       [LoRA 어댑터 추가]
       (학습 파라미터: 1.3% → 0.6%)
              ↓
     [합성 데이터셋 로드]
     (Train: 800개, Test: 200개)
              ↓
     [SFTTrainer로 파인튜닝]
     (배치 8, 학습률 2e-4, 1 에포크)
              ↓
      [모델 체크포인트 저장]
              ↓
   [테스트셋으로 성능 평가]
              ↓
   [FastAPI로 API 래핑]
              ↓
   [ngrok으로 배포 준비 완료]
```

### 3.4 데이터 전처리 파이프라인

| 단계 | 작업 | 결과 |
|------|------|------|
| **1. 로딩** | JSON 원본 데이터 읽기 | 원본 메시지 |
| **2. 포맷팅** | User A(가해자)/B(피해자) 형식 변환 | 시퀀스 데이터 |
| **3. 레이블링** | 그루밍(1) / 정상(0) 부여 | 레이블 추가 |
| **4. 필터링** | 최소 4개 메시지 이상만 선별 | 유효 샘플만 유지 |
| **5. 분할** | Train 80% / Test 20% 분할 | 학습/테스트 분리 |
| **6. 저장** | HuggingFace Dataset 포맷 | 파인튜닝 준비 완료 |

## 7. 핵심 기술 혁신

### 7.1 메모리 최적화 기술

```python
# 기존 (Full Fine-tuning): 70GB GPU 필요
model = AutoModelForCausalLM.from_pretrained(model_name)

# 우리의 방식 (QLoRA): 16GB GPU로 충분
bnb_config = BitsAndBytesConfig(load_in_4bit=True)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=bnb_config
)
```

- ✅ 메모리 70% 절감


**결과:**
- ✅ 6,400가지 조합 가능

## 10. 면접 대비 핵심 답변

### Q1. "이 프로젝트에서 가장 자랑스러운 부분은?"

**답변:**
> "LLM 파인튜닝 시 메모리 최적화에 집중했습니다. 기존 방식으로는 A5000 (24GB)도 부족했는데, **4-bit 양자화 + LoRA 조합으로 메모리를 70% 절감**해 더 빠르고 저렴한 GPU에서도 학습 가능하게 만들었습니다. 이는 **스타트업이나 소규모 팀이 대규모 모델을 활용할 수 있는 실무 기술**로서 즉시 적용 가능합니다."

### Q2. "데이터 생성 파이프라인이 특별한 이유는?"

**답변:**
> "기존 방식은 실제 민감한 그루밍 대화를 수집해야 하는데, 개인정보보호법과 윤리 문제가 심각합니다. 저는 **Llama를 활용한 합성 데이터 생성**으로 이를 극복했습니다. Few-shot 프롬프트로 40×40×4의 **6,400가지 가능 조합**을 자동 생성하고, 이를 분류기 학습에 사용했습니다. 이는 **데이터 희소 분야의 AI 연구에 새로운 접근법**을 제시합니다."

### Q3. "실제 운영 서비스에서는 어떻게 확장할 계획입니까?"

**답변:**
> "현재는 프로토타입이지만, FastAPI + ngrok으로 **실시간 API 제공**이 가능합니다. 카카오톡/디스코드 봇으로 확장하면 **실제 플랫폼에서 즉시 위험 메시지를 탐지**할 수 있습니다. 또한 경찰청 사이버수사팀과 협력해 **비식별 실제 데이터**를 통합하고, 멀티모달(이미지+음성) 분석으로 확장할 계획입니다. 장기적으로는 **Kubernetes 기반 마이크로서비스** 아키텍처로 대규모 배포를 목표로 합니다."

### Q4. "프로젝트 중 어려웠던 부분과 해결 방법은?"

**답변:**
> "가장 큰 도전은 **현실적인 합성 데이터 생성**이었습니다. 초기에는 프롬프트가 단순해서 패턴이 반복되고 부자연스러웠습니다. 이를 해결하기 위해:
> 1. Few-shot 예시를 프롬프트에 포함
> 2. 페르소나 조합을 40×40으로 다양화
> 3. 단계별 목표를 상세히 명시
> 4. 생성된 데이터의 품질 필터링 추가
>
> 그 결과 **1,000개의 현실적인 그루밍 시나리오**를 성공적으로 생성했고, 모델이 **다양한 상황을 학습**할 수 있게 되었습니다."
